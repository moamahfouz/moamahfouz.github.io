Part 1

Warmup — OS, SSH & Security

01 OS Introduction ▼

An Operating System (OS) is the software that manages your computer's hardware and lets you run programs. Think of it as the building manager — it decides who gets which room (memory), who uses the elevator (CPU), and controls the doors (I/O devices).

⚙ Key Concepts
  • Kernel — the core that talks directly to hardware
  • Shell — the interface you type commands into
  • Process — any running program
  • File System — how files are stored and organized
▶ Example: Windows, macOS, and Linux are all operating systems. Linux is used on most servers worldwide, in Android phones, and in supercomputers.
02 Virtual Machine Introduction ▼

A Virtual Machine (VM) is a computer inside your computer. It runs its own OS without affecting your real system, using software called a hypervisor.

💡 Why Use a VM?
  • Safely try Linux without breaking your main OS
  • Test software in an isolated sandbox
  • Run multiple OSes at the same time
▶ Example: VirtualBox is a free hypervisor. Install it on Windows, then create a VM that runs Ubuntu Linux inside a window.
💡 Think of a VM like a sandbox — you can build and destroy things without affecting the real world outside.
03 OS Evolution History ▼

Understanding history helps you understand why Linux works the way it does today.

📅 Timeline
  • 1969 — Unix created at Bell Labs. Simple, powerful, influential design.
  • 1983 — GNU Project by Richard Stallman (free software movement)
  • 1991 — Linus Torvalds creates the Linux kernel as a hobby project
  • 1992 — Linux + GNU tools = a complete free operating system
  • 2000s+ — Linux dominates servers, powers Android, runs supercomputers
▶ Example: When you use an Android phone, you're running Linux under the hood!
04 Create Local Ubuntu VM using VirtualBox ▼
📋 Steps
  • Download VirtualBox from virtualbox.org and install it
  • Download the Ubuntu ISO from ubuntu.com/download
  • Open VirtualBox → New → Name it "Ubuntu" → Choose Linux type
  • Assign RAM (2 GB minimum, 4 GB recommended)
  • Create a virtual hard disk (20 GB+)
  • Start the VM, select the Ubuntu ISO, follow the installer
💡 After install, install Guest Additions for better screen resolution and copy-paste support.
05 Bash and Terminal Introduction ▼

The terminal is a text window where you type commands. Bash is the most popular shell (command interpreter) on Linux.

⌨ First Commands
bash 
$ whoami         # shows your username
$ pwd            # shows current directory (where you are)
$ ls             # lists files in current directory
$ echo Hello     # prints Hello to the screen
$ date           # shows current date and time
💡 $ means "type here as a normal user". # starts a comment — not executed.
▶ Try it: Open a terminal and type: echo 'I am learning Linux!'
06 Linux Distros Overview ▼

A Linux distro (distribution) is Linux + a collection of tools packaged together. There are hundreds, but a few dominate.

🐧 Popular Distros
  • Ubuntu — most beginner-friendly, huge community, great for desktops & servers
  • Debian — very stable, Ubuntu is based on it
  • CentOS / RHEL — popular in enterprise servers
  • Arch Linux — for advanced users who want full control
  • Kali Linux — security and penetration testing
▶ Recommendation: Start with Ubuntu. It has the most tutorials, packages, and community support.
07 Activate WSL on Windows ▼

WSL (Windows Subsystem for Linux) lets you run Linux commands directly inside Windows — no VM needed. Built into Windows 10/11.

🔧 How to Enable WSL
powershell 
# Open PowerShell as Administrator:
wsl --install

# After restart, open 'Ubuntu' from Start Menu
# Create a username and password when prompted
▶ After setup: You can run ls, grep, and all Linux commands inside Windows via the Ubuntu app.
💡 WSL2 is faster and runs a real Linux kernel inside Windows.
08 Diffie-Hellman Key Exchange ▼

Diffie-Hellman is a way for two people to secretly agree on a shared key over a public network — without ever sending the key itself.

🎨 Simple Analogy

Imagine you and a friend want to agree on a secret color. You both start with a public color (yellow). You each mix in your own private color, swap the result, then mix in your private color again — you both end up with the same final color without ever revealing your private one!

📌 Why It Matters
  • Used in SSH, HTTPS, and VPNs
  • Allows secure communication over insecure networks (the internet)
▶ Example: Every time you visit https:// in a browser, Diffie-Hellman helps establish a secure session.
09 MAC, Digital Signatures & RSA ▼

Tools that ensure data hasn't been tampered with and verify who sent it.

🔐 Concepts
  • MAC (Message Authentication Code) — a checksum proving a message hasn't changed
  • Digital Signature — mathematical proof of who sent a message
  • RSA — popular public-key encryption. Uses two keys: public (share it) and private (keep it secret)
📬 RSA Analogy

Think of a mailbox: anyone can drop a letter in (public key), but only you have the key to open it (private key).

▶ Example: When you run ssh-keygen, you create an RSA key pair — a public and a private key.
10 SSH Introduction ▼

SSH (Secure Shell) lets you securely log into and control a remote Linux server over the network. All traffic is encrypted.

📌 Key Points
  • Default port: 22
  • Everything sent is encrypted — passwords included
  • Used daily by developers, sysadmins, and DevOps engineers
bash 
# Basic SSH format:
ssh username@server_ip

# Example:
ssh john@192.168.1.100
💡 SSH replaced older insecure tools like Telnet where passwords were sent as plain text.
11 SSH — Connect Using Password ▼

The simplest way: type your username, IP address, and enter your password when prompted.

bash 
$ ssh ahmed@192.168.1.50
ahmed@192.168.1.50's password:
# Type password (nothing shows — that's normal!)
Welcome to Ubuntu 22.04 LTS
ahmed@server:~$   ← You're now on the remote machine!

# Useful options:
ssh -p 2222 user@host   # use port 2222 instead of 22
ssh -v user@host        # verbose: debug connection issues
💡 Password login is convenient but less secure. Use key-based auth (Lesson 12) for production servers.
12 SSH — Connect Using Key Pairs ▼

Instead of a password, you prove identity using a key pair. More secure and no typing passwords!

bash 
# Step 1: Generate key pair (on YOUR local machine)
$ ssh-keygen -t rsa -b 4096
# Creates: ~/.ssh/id_rsa (private) and ~/.ssh/id_rsa.pub (public)

# Step 2: Copy your PUBLIC key to the server
$ ssh-copy-id ahmed@192.168.1.50

# Step 3: Login without password!
$ ssh ahmed@192.168.1.50   # No prompt!
💡 NEVER share your private key (id_rsa). The public key (id_rsa.pub) is safe to share with anyone.
13 Unix Philosophy ▼

The Unix Philosophy is a set of design principles that make Linux tools powerful and composable.

📜 The Three Rules
  • 1. Write programs that do one thing and do it well
  • 2. Write programs that work together
  • 3. Write programs that handle text — text is the universal interface
▶ Example: Instead of one giant program, Linux has: ls (list), grep (search), sort (sort), wc (count). Chain them with pipes!
bash 
# Count files containing 'error' in /var/log:
$ grep -r 'error' /var/log | wc -l
Part 2

Files — Navigation, Editing & Tools

14 Navigating Directories ▼

Linux uses a tree-like directory structure. Everything starts from / (called "root").

bash 
$ pwd              # Print Working Directory — where am I?
$ ls               # list files
$ ls -la           # list ALL files with details (permissions, size)
$ cd /home/ahmed   # go to /home/ahmed
$ cd ..            # go up one level
$ cd ~             # go to your home directory
$ cd -             # go to previous directory
💡 ~ = your home dir (e.g. /home/ahmed). . = current dir. .. = parent dir.
15 Create, Delete, Copy, and Move Files ▼
bash 
# Creating
$ touch myfile.txt        # create empty file
$ mkdir myfolder          # create directory
$ mkdir -p a/b/c          # create nested dirs

# Deleting
$ rm myfile.txt           # delete file
$ rm -rf myfolder/        # delete folder + everything inside

# Copying & Moving
$ cp file.txt backup.txt  # copy file
$ cp -r folder/ backup/   # copy folder recursively
$ mv file.txt /tmp/       # move file
$ mv old.txt new.txt      # rename file
⚠️ rm -rf has NO undo! Always double-check your path. rm -rf / would delete your entire system.
16 Introduction to Vim ▼

Vim is a powerful terminal text editor. It has modes — you switch between them to navigate or type.

🔑 Essential Commands
vim 
$ vim myfile.txt   # open file

i                  # enter INSERT mode (start typing)
ESC                # return to NORMAL mode
:w                 # save the file
:q                 # quit
:wq                # save and quit
:q!                # quit WITHOUT saving (escape!)
dd                 # delete current line
/word              # search for 'word'
u                  # undo
💡 Stuck in Vim? Press ESC then type :q! to exit without saving.
17 Piping, cat, sort, tail, echo, and tr ▼
bash 
$ cat file.txt             # print file to screen
$ echo 'Hello World'       # print text
$ sort names.txt           # sort lines alphabetically
$ tail -n 5 file.txt      # show last 5 lines
$ tail -f /var/log/syslog # follow log in real time
$ echo 'hello' | tr 'a-z' 'A-Z'  # → HELLO

# Chaining with pipes (|):
$ tail -n 100 /var/log/auth.log | grep 'Failed'
$ sort names.txt | uniq    # sort and remove duplicates
💡 The pipe | sends output of one command as input to the next. This is the Unix Philosophy in action!
18 Everything is a File ▼

In Linux, almost everything is represented as a file — not just documents, but hardware devices, network connections, and running processes too.

📂 Special Files
  • /dev/sda — your hard drive
  • /dev/null — a black hole. Write to it to discard output.
  • /dev/zero — produces infinite zeros
  • /proc/cpuinfo — information about your CPU (a virtual file!)
  • /proc/meminfo — current memory usage
bash 
$ cat /proc/cpuinfo          # see your CPU details
$ cat /proc/meminfo          # see memory breakdown
$ echo 'discard' > /dev/null # throw away output
19 Linux Filesystem Hierarchy Standard ▼

Linux organizes files in a standardized tree. Knowing where things live makes you faster.

📁 Key Directories
  • / — Root of everything
  • /home — User home directories (/home/ahmed)
  • /etc — Config files (/etc/hosts, /etc/passwd)
  • /var — Variable data: logs, databases (/var/log/syslog)
  • /tmp — Temporary files (cleared on reboot)
  • /bin — Basic commands (ls, cp, mv)
  • /usr — User programs and libraries
  • /dev — Device files
  • /proc — Virtual files about running processes
  • /boot — Bootloader and kernel
▶ Rule of thumb: Config → /etc. Logs → /var/log. Your files → /home.
20 Redirection — stdin, stdout, stderr ▼

Every Linux process has 3 standard streams: input (0), output (1), and error (2).

bash 
$ ls > output.txt        # save stdout to file (overwrites)
$ ls >> output.txt       # append stdout to file
$ cat < input.txt        # read stdin from file
$ ls /badpath 2> err.txt  # save errors (stderr) to file
$ command > out.txt 2>&1  # save BOTH stdout and stderr
$ command > /dev/null 2>&1 # silence ALL output
21 Compare and Search for Files ▼
bash 
# find — search by name, size, type
$ find / -name 'myfile.txt'        # find by name
$ find /home -name '*.log'         # all .log files
$ find /tmp -type f -mtime +7      # files older than 7 days
$ find . -size +10M               # files larger than 10MB

# diff — compare two files
$ diff file1.txt file2.txt          # show differences
$ diff -u file1.txt file2.txt      # unified format (like git diff)
22 grep — Search Inside Files ▼

grep searches for text patterns inside files. One of the most-used Linux tools.

bash 
$ grep 'error' /var/log/syslog   # find lines with 'error'
$ grep -i 'error' file.txt        # case-insensitive
$ grep -r 'password' /etc/        # recursive (all files)
$ grep -n 'TODO' mycode.py         # show line numbers
$ grep -v 'debug' app.log          # lines NOT matching
$ grep -c 'error' file.txt         # count matching lines
$ ps aux | grep nginx              # find nginx process
▶ Real use: grep -r 'PermitRootLogin' /etc/ssh/ — check if root SSH login is allowed.
23 sed — Stream Editor ▼

sed processes text line by line. Most commonly used for search-and-replace.

bash 
# Replace first 'old' with 'new' per line:
$ sed 's/old/new/' file.txt

# Replace ALL occurrences (g = global):
$ sed 's/old/new/g' file.txt

# Edit file in-place (saves changes):
$ sed -i 's/old/new/g' file.txt

# Delete lines containing 'debug':
$ sed '/debug/d' file.txt

# Print only lines 5-10:
$ sed -n '5,10p' file.txt
▶ Example: sed -i 's/localhost/0.0.0.0/g' config.conf — change all localhost to 0.0.0.0.
24 awk — Text Processing Tool ▼

awk processes text column by column. Perfect for structured data like logs or CSV files.

bash 
$ awk '{print $1}' file.txt         # print 1st column
$ awk '{print $1, $3}' file.txt     # print columns 1 and 3
$ awk '$3 > 100' file.txt           # lines where col 3 > 100
$ awk -F',' '{print $2}' data.csv    # use comma as separator
$ df -h | awk '$5+0 > 80 {print}'   # disks over 80% full
▶ Real use: awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn — top IPs hitting your server.
25 Virtual File System (VFS) ▼

VFS is a layer inside the Linux kernel that provides a unified interface for all filesystems. It means you can use the same commands (ls, cat, cp) on ext4, NFS, FAT32, and more.

💾 Common Filesystems
  • ext4 — standard Linux disk filesystem
  • tmpfs — lives in RAM (fast, lost on reboot)
  • procfs — the /proc virtual filesystem
  • sysfs — /sys for device info
▶ Example: mount -t tmpfs tmpfs /mnt/ramdisk — creates a super-fast RAM disk.
26 Hard and Soft Links ▼
🔗 Hard Link

Another name for the same file data. Deleting one name doesn't delete the data — the data is gone only when ALL hard links are removed.

bash 
$ ln original.txt hardlink.txt      # create hard link
$ ln -s original.txt symlink.txt     # create soft/symbolic link
$ ls -la symlink.txt                 # shows: symlink.txt -> original.txt
▶ Example: /usr/bin/python3 is often a symlink to /usr/bin/python3.11
Part 3

Processes — Execution, IPC & Sync

27 System Calls ▼

A system call (syscall) is how a program asks the OS kernel to do something it can't do alone — read a file, create a process, or send data over the network.

📋 Common System Calls
  • open() / read() / write() / close() — file operations
  • fork() — create a new process
  • exec() — run a new program
  • exit() — end a process
  • socket() / connect() — network operations
bash 
# See what syscalls a command makes:
$ strace ls
▶ Example: When you run cat file.txt, cat calls open(), then read() in a loop, then write() to print, then close().
28 Interrupts ▼

An interrupt is a signal that tells the CPU to stop what it's doing and handle something urgent — a keypress, network packet, or disk completion.

⚡ Types
  • Hardware Interrupts — from devices (keyboard, NIC, disk)
  • Software Interrupts — triggered by programs (division by zero, system calls)
🔄 How It Works

Device signals interrupt → CPU pauses current task → Runs interrupt handler → Returns to original task.

bash 
$ cat /proc/interrupts   # view interrupt counts per CPU
💡 Interrupts are why you can type while a file downloads — the CPU handles each event as it arrives.
29 Processes & Threads ▼

A process is a running program with its own memory space. A thread is a lightweight execution unit within a process — threads share memory.

⚖ Key Difference
  • Process — isolated memory, more overhead, safer
  • Thread — shared memory, less overhead, faster but riskier (data races)
bash 
$ ps aux                 # list all running processes
$ ps aux | grep nginx    # find nginx processes
$ kill 1234              # send SIGTERM to PID 1234
$ kill -9 1234           # force kill (SIGKILL)
$ pstree                 # show process tree
▶ Example: A browser has one process per tab but multiple threads per tab for rendering, JS, and networking.
30 CPU Scheduler ▼

The scheduler decides which process runs on the CPU and for how long. It takes turns rapidly, creating the illusion of parallel execution.

📌 Key Concepts
  • Context Switch — saving one process's state and loading another's
  • Time Slice — max time a process gets before being preempted
  • CFS (Completely Fair Scheduler) — Linux's default scheduler
bash 
$ nice -n 10 my_program    # run with lower priority
$ renice -n -5 -p 1234     # change priority of running process
▶ Example: Video encoding can run at nice +19 so it doesn't slow down your browser.
31 IPC — Signals ▼

Signals are software notifications sent to a process to tell it something happened.

📡 Common Signals
  • SIGTERM (15) — please stop gracefully
  • SIGKILL (9) — stop NOW, cannot be caught or ignored
  • SIGHUP (1) — reload configuration
  • SIGINT (2) — interrupt (Ctrl+C)
  • SIGSTOP (19) — pause process (Ctrl+Z)
bash 
$ kill -15 1234       # graceful stop
$ kill -9 1234        # force stop
$ kill -1 1234        # reload config
$ pkill nginx         # kill by name
$ killall firefox     # kill all firefox processes
💡 Always try SIGTERM first. Only use SIGKILL if the process doesn't respond — it won't clean up temp files.
32 IPC — Pipes ▼

A pipe is a one-way communication channel — the output of one process becomes the input of another.

bash 
# Anonymous pipe:
$ ls | grep '.txt'

# Named pipe (FIFO):
$ mkfifo mypipe
$ echo 'hello' > mypipe &  # write (background)
$ cat mypipe               # read
33 IPC — Message Queues & Shared Memory ▼
📨 Message Queues

Lets processes send structured messages to each other. Messages wait in the queue until picked up. Unlike pipes, messages have types and can be read out of order.

🧠 Shared Memory

The fastest IPC method — two processes share the same region of RAM and read/write directly. No data is copied. But you must synchronize access (with mutex/semaphore) to avoid conflicts.

bash 
$ ipcs -q    # show message queues
$ ipcs -m    # show shared memory
$ ipcs -s    # show semaphores
34 Synchronization — Mutex ▼

A Mutex (Mutual Exclusion lock) ensures only one process/thread can access a shared resource at a time.

⚠ The Race Condition Problem

Two threads both read a counter (value: 5), both add 1, both write back. Expected: 7. Actual: 6. Both read 5 before either wrote 6.

✅ The Mutex Solution

Before touching the counter, a thread locks the mutex. Other threads wait. After updating, the thread unlocks it.

⚠️ Deadlock: Thread A holds Lock 1 waiting for Lock 2, while Thread B holds Lock 2 waiting for Lock 1 — they wait forever!
35 Synchronization — Semaphore ▼

A semaphore is like a counter that controls access to a resource. Unlike a mutex (1 user at a time), a semaphore can allow N users simultaneously.

🅿 Analogy: Parking Lot

A parking lot with 5 spaces. Semaphore starts at 5. Each car entering decrements it; leaving increments it. When it hits 0, new cars wait.

bash 
$ ipcs -s          # view semaphores
$ ipcrm -s <semid>  # remove semaphore
▶ Example: A database connection pool uses a semaphore to limit concurrent connections (e.g., max 100).
36 Synchronization — File Lock ▼

File locks prevent multiple processes from writing the same file simultaneously.

🔒 Types
  • Shared Lock (read) — multiple readers OK
  • Exclusive Lock (write) — only one writer at a time
bash 
$ cat /proc/locks                        # check file locks
$ flock -x /tmp/mylock.lock my_script.sh  # exclusive lock in scripts
Part 4

Memory — Pages, Virtual Memory & Policy

37 Memory Pages ▼

The OS doesn't manage memory byte-by-byte — it uses fixed-size chunks called pages (usually 4KB). This makes memory management efficient.

📊 Key Facts
  • Default page size: 4,096 bytes (4KB)
  • Huge Pages: 2MB or 1GB — for performance-sensitive apps
  • The kernel uses a page table to map virtual → physical addresses
bash 
$ getconf PAGE_SIZE              # check page size (usually 4096)
$ cat /proc/meminfo | grep Huge  # hugepage info
$ vmstat 1                        # view page faults live
💡 A "page fault" isn't always an error — it often means the kernel needs to load a page from disk into RAM.
38 Virtual Memory ▼

Every process thinks it has the entire computer's memory to itself — that's the illusion created by virtual memory. The kernel maps virtual addresses to real physical RAM behind the scenes.

✅ Benefits
  • Isolation — one process can't read another's memory
  • More than physical RAM — using swap space on disk
  • Simplified programming — every process starts at address 0
bash 
$ cat /proc/1234/maps   # view process memory map (PID 1234)
$ pmap 1234             # user-friendly memory map
39 Linux Memory Management Setup ▼

Linux uses all available RAM productively — idle RAM is wasted RAM.

⚙ Key Mechanisms
  • Page Cache — recently read files cached in RAM for speed
  • Swap — when RAM is full, least-used pages move to disk
  • OOM Killer — when memory is critically low, kills processes
bash 
$ free -h              # show RAM and swap usage
$ swapon --show        # show swap devices

# Create a 2GB swap file:
$ fallocate -l 2G /swapfile
$ chmod 600 /swapfile
$ mkswap /swapfile
$ swapon /swapfile
40 Overcommit Policy ▼

Linux allows overcommitting memory — letting processes allocate more virtual memory than physically exists. This works because most programs never use all the memory they allocate.

🔢 Modes
  • 0 (default) — heuristic: allow reasonable overcommit
  • 1 — always allow, never fail malloc()
  • 2 — strict: never allow more than RAM + swap
bash 
$ cat /proc/sys/vm/overcommit_memory   # current mode
$ cat /proc/sys/vm/overcommit_ratio    # ratio setting

# Temporarily change (until reboot):
$ echo 2 > /proc/sys/vm/overcommit_memory
Part 5

Monitoring — Memory & Processes

41 Memory Monitoring ▼
bash 
$ free -h                      # quick RAM + swap overview
$ vmstat 1                      # memory stats every 1 second
$ cat /proc/meminfo             # full memory breakdown
$ top                           # interactive: memory per process
$ htop                          # better top (apt install htop)

# Watch memory every 2 seconds:
$ watch -n 2 free -h

# Top 5 memory-hungry processes:
$ ps aux --sort=-%mem | head -6
💡 Don't panic if "available" memory looks low — Linux uses RAM for caching. Watch MemAvailable, not MemFree.
42 Process Monitoring ▼
bash 
$ top               # interactive process monitor (q to quit)
$ htop              # colorful, easier top
$ ps aux            # snapshot of all processes
$ pgrep nginx       # find PID by name
$ lsof -p 1234      # files opened by process
$ strace -p 1234    # trace syscalls of running process
$ pstree -p        # show process tree with PIDs

# Watch a specific process every 1s:
$ watch -n 1 'ps aux | grep myapp'
📊 Key ps Columns
  • PID — Process ID
  • %CPU — CPU usage percentage
  • %MEM — RAM usage percentage
  • RSS — Resident Set Size (actual RAM used)
  • STAT — R=running, S=sleeping, Z=zombie, T=stopped
