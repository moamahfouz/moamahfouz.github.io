IT Setup Guide · LDAP Bridge

Active Directory Authentication Bridge

Instructions for deploying the Node.js bridge service on an internal server and exposing it securely.

BEFORE YOU START

What You Need

Internal Server Any Windows or Linux machine inside the company network that can reach Active Directory
Node.js Version 18 or higher — nodejs.org
Internet access The internal server needs outbound internet to download packages (or IT can use a local mirror)
AD details Hostname of the AD server (e.g. server02.rahili.local) and the domain name (e.g. rahili.local)
Project files The ldap-bridge folder provided — copy it to the internal server
STEP 01

Install Node.js on the Internal Server

Run the appropriate commands for the server OS:

Ubuntu / Debian Linux 
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
# Verify installation
node --version
Windows Server (PowerShell) 
# Download installer from:
https://nodejs.org/en/download
# After install, verify:
node --version
STEP 02

Copy Files & Configure

  1. Copy the ldap-bridge folder to the internal server.
    Suggested path: C:\ldap-bridge on Windows  /  /opt/ldap-bridge on Linux
  2. Open a terminal inside the ldap-bridge folder and run:
    Terminal 
    npm install
  3. Create the config file — copy the example and rename it:
    Linux 
    cp .env.example .env
    Windows 
    copy .env.example .env
  4. Edit the .env file with a text editor and fill in these values:
    .env 
    PORT=3000
API_SECRET_KEY=replace-this-with-a-long-random-password
LDAP_URL=ldap://server02.rahili.local
LDAP_BASE_DN=DC=rahili,DC=local
LDAP_DOMAIN=rahili.local
    ⚠️

    API_SECRET_KEY is the password between the bridge and the Laravel server. Make it long and random (e.g. xK9@mP2#vR7!qL4$nW). Share this value with the developer — it goes into Laravel's .env file.

STEP 03

Test the Connection to Active Directory

Before going further, confirm the server can reach AD:

Terminal — ping test 
ping server02.rahili.local
✅

Expected: You get replies with an IP address. This confirms the internal server can see Active Directory.

❌

If ping fails: The internal server is not on the same network as Active Directory. Contact the network team to fix routing before continuing.

STEP 04

Run the Bridge Service

Start (test) 
npm start
# You should see:
[INFO] LDAP Bridge running on port 3000
[INFO] LDAP server: ldap://server02.rahili.local

For production — keep it running permanently with PM2:

PM2 — permanent background service 
# Install PM2 globally (one time)
npm install -g pm2

# Start the bridge
pm2 start server.js --name ldap-bridge

# Auto-start on server reboot
pm2 save
pm2 startup
ℹ️

PM2 will keep the bridge running even after reboots. To check status anytime: pm2 status

STEP 05

Expose It with a Public Domain (nginx + HTTPS)

The bridge runs on localhost:3000. To make it reachable from the Laravel server on the internet, you need nginx as a reverse proxy with HTTPS. This is the safest way — the bridge is never directly exposed, only nginx is.

  1. Point a domain to this server's public IP.
    Example: create an A record → ldap-bridge.yourcompany.com → your.server.public.ip
  2. Install nginx and Certbot (for free HTTPS certificate):
    Ubuntu / Debian 
    sudo apt install -y nginx certbot python3-certbot-nginx
  3. Create nginx config — create file /etc/nginx/sites-available/ldap-bridge:
    nginx config 
    server {
    listen 80;
    server_name ldap-bridge.yourcompany.com;

    location / {
        proxy_pass         http://127.0.0.1:3000;
        proxy_http_version  1.1;
        proxy_set_header    Host              $host;
        proxy_set_header    X-Real-IP         $remote_addr;
        proxy_set_header    X-Forwarded-For   $proxy_add_x_forwarded_for;
    }
}
  4. Enable the config and get HTTPS certificate:
    Terminal 
    sudo ln -s /etc/nginx/sites-available/ldap-bridge /etc/nginx/sites-enabled/
sudo nginx -t           # test config — should say "ok"
sudo systemctl reload nginx

# Get free HTTPS certificate (follow prompts)
sudo certbot --nginx -d ldap-bridge.yourcompany.com
  5. Restrict access by IP — only allow the Laravel server, block everything else.
    Add this inside the location / block in the nginx config:
    nginx — IP whitelist 
    allow  LARAVEL_SERVER_IP;   # ← replace with real IP
deny   all;
    🔒

    This is critical. IP whitelisting means even if someone discovers the URL, they cannot reach the bridge. Only the Laravel server can talk to it.

  6. Reload nginx to apply all changes:
    Terminal 
    sudo systemctl reload nginx
STEP 06

Verify Everything Works

Run this from any machine to confirm the bridge is live:

Health check 
curl https://ldap-bridge.yourcompany.com/health
✅

Expected response:
{"status":"ok","service":"ldap-bridge","timestamp":"2025-..."}

Test an actual AD login:

Auth test 
curl -X POST https://ldap-bridge.yourcompany.com/auth \
  -H "Content-Type: application/json" \
  -H "X-Api-Key: your-secret-key" \
  -d '{"username":"john.doe","password":"their-password"}'
📩

Send to the developer once done: The public URL (https://ldap-bridge.yourcompany.com) and the API_SECRET_KEY value from the .env file. That's all they need to wire up Laravel.
